# Local Dev Docs
**Русский** | [English](README.md)

Локальная документация для заметок по Laravel, PHP, Git, собеседованиям и рабочим шпаргалкам.

## Как это устроено

Проект состоит из:

- `public/index.php` — главная страница и генерация меню из папок
- `public/block.php` — безопасная отдача HTML-блоков
- `src/Auth.php` — helper для HTTP Basic авторизации
- `public/assets/js/app.js` — стартовый скрипт инициализатор
- `public/assets/js/core/App.js` — главный скрипт приложения
- `public/assets/js/modules` — модули приложения для загрузки документов, поиска и содержания текущей статьи
- `public/assets/css/app.css` — стили
- `storage/blocks/` — сами документы в виде отдельных `.html` файлов

Содержание синхронизировано с текущим документом: скролл страницы двигает содержание, а скролл содержания двигает страницу по тому же прогрессу прокрутки.

## Как это работает

1. `index.php` сканирует папку `storage/blocks`
2. Находит все `.html` файлы
3. Строит меню автоматически по структуре папок
4. При клике JS запрашивает нужный блок через `block.php`
5. `block.php` проверяет путь и отдаёт только разрешённый `.html` файл
6. После загрузки документа JS строит содержание по его заголовкам

## Как запускать

Из папки `public`:

```bash
php -S localhost:9999
```

После этого открыть в браузере:

<a href="http://localhost:9999" target="_blank">http://localhost:9999</a>

## Basic авторизация

HTTP Basic авторизация выключена по умолчанию для локальной разработки.

На сервере её нужно включить через переменные окружения:

```bash
DOCS_AUTH_ENABLED=1
DOCS_AUTH_USER=admin
DOCS_AUTH_PASSWORD=change-me
```

И `public/index.php`, и `public/block.php` проверяют один и тот же логин/пароль, поэтому прямые запросы к HTML-блокам тоже защищены.

Если задать `DOCS_AUTH_ENABLED=1`, но не задать `DOCS_AUTH_USER` или `DOCS_AUTH_PASSWORD`, приложение вернёт `500` и не откроется публично. Настоящие пароли нельзя коммитить. Их нужно задавать на сервере, в Docker или в настройках облачного сервиса.

## Docker

Создать `.env` файл на сервере:

```bash
cp .env.example .env
```

Потом отредактировать `.env`:

```env
DOCS_HOST_PORT=9999
DOCS_AUTH_ENABLED=1
DOCS_AUTH_USER=admin
DOCS_AUTH_PASSWORD=your-real-password
```

Запустить контейнер с примонтированными файлами проекта:

```bash
docker-compose up -d --build
```

После этого открыть:

```text
http://SERVER_IP:9999
```

`DOCS_HOST_PORT` управляет портом сервера. Например, `DOCS_HOST_PORT=18080` откроет `http://SERVER_IP:18080`.

Внутри Docker контейнер слушает порт `9999`. На сервер наружу открывается только порт из `DOCS_HOST_PORT`.

В compose не задан фиксированный `container_name`, поэтому Docker Compose сам создаёт имя контейнера с префиксом проекта и не конфликтует с другими контейнерами по имени. Обычно конфликтовать может только внешний порт; если `9999` уже занят, поменяй `DOCS_HOST_PORT`.

В compose примонтированы эти папки:

```text
./public  -> /app/public
./src     -> /app/src
./storage -> /app/storage
```

Значит можно править документы в `storage/blocks`, PHP-код, CSS и JavaScript прямо на сервере без пересборки образа. Если поменял `.env`, пересоздай контейнер:

```bash
docker-compose up -d
```

Остановить контейнер:

```bash
docker-compose down
```

Файл `.env` игнорируется Git. Коммитить нужно только `.env.example`, настоящий `.env` с паролем не коммитится.

## Как добавлять новые статьи

Просто создать новый `.html` файл внутри `storage/blocks`.

Примеры:

```text
storage/blocks/laravel/queues.html
storage/blocks/php/interfaces.html
storage/blocks/interviews/laravel/middleware-short.html
```

После обновления страницы новый файл автоматически появится в меню.

## Важные правила

- Блоки документации хранятся только в `storage/blocks`
- Разрешены только файлы `.html`
- Структура меню строится из папок автоматически
- Если файл не появился, проверь расширение и путь
- Если меняется код проекта, обновляй `README.md` и `README_ru.md`, когда меняется поведение, структура или способ запуска

## Для чего нужен `block.php`

`block.php` нужен для безопасной загрузки блоков.

Он:

- принимает путь к файлу
- проверяет, что файл реально находится внутри `storage/blocks`
- запрещает выход за пределы папки
- отдаёт только `.html`

Это нужно, чтобы случайно не открыть `.env`, `.php`, `.json` или другие лишние файлы.

## Если что-то не работает

### Не грузится блок
Проверь:

- запущен ли локальный PHP-сервер
- существует ли файл
- правильный ли путь
- имеет ли файл расширение `.html`

### Новый файл не появился в меню
Проверь:

- лежит ли он внутри `storage/blocks`
- расширение файла точно `.html`
- нет ли ошибки в названии папки
